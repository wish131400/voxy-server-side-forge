# VSS 与 Voxy 的帧率差异及固定 GPU 场景改造

Forge 1.20.1 与 NeoForge 1.21.1 使用同一套场景记录、变更日志和提交编码逻辑，平台调用保持各自差异。完整说明、实测背景、适用范围和未完成的架构差距见 NeoForge 仓库同名报告；本仓库的验证产物位于 `build-persistent-scene-20261015` 与 `lib/persistent-scene-20261015`。

本轮固定 GPU scene 在满足现有常驻不透明 GPU 选择策略时使用稳定 metadata 槽、固定命令区间和局部变更编码，减少转向时对静态提交数据的重建。Forge 隐藏 GPU 回归结果如下：

| 场景 | 原有有序提交 | 固定 GPU scene | 下降 |
| --- | ---: | ---: | ---: |
| 静态场景原地转向 | 0.465756 ms/pass | 0.281469 ms/pass | 39.6% |
| 每帧更新一个网格元数据 | 1.551591 ms/pass | 1.184153 ms/pass | 23.7% |

该基准包含 12 轮预热、21 轮测量、每轮 32 帧和 GPU 完成等待，但不包含完整游戏 FPS、全部场景准备、区块生成或真实森林。Forge CPU 回归 85 个、GPU 回归 11 个，失败、错误和跳过均为 0。JAR SHA256 记录在 `SHA256SUMS.txt`，验证详情在 `validation.json`。

这项改造不能说明 VSS 已经等价于 Voxy。Voxy 仍具有同源 2x2x2 逐级 mip、GPU 父子层级遍历、屏幕误差选择和粗层回退；VSS 仍需在 CPU 上处理覆盖、接缝、特殊模型、透明排序和版本交接，GPU scene 目前只覆盖合资格的不透明整段范围。持续低帧仍应优先检查渲染线程的场景准备和实际选中几何量，而不是只看 GPU 总利用率。

本轮没有启动客户端、替换实例或推送 GitHub。用户可自行替换 `lib/persistent-scene-20261015/vss-0.3.5-forge-1.20.1.jar` 后，在相同位置分别测试静止、转向、跑图和森林场景。
