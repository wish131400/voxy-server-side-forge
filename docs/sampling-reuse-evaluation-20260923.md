# 相邻洞口采样复用评估（2026-09-23）

这项离线评估现已落到源码中的生产采样路径；现有已发布 JAR 不会自动改变。目标是比较逐个 `Terrain::exterior_footprint` 请求和相邻请求在水平噪声格内复用 `Job`/`Scratch` 的结果，不降低高度、液体或洞口占用的精度。

## 输入与方法

- 实际山体：只读世界生成快照、种子 `5052304137288917019`，区域 `(-4588, -1531)` 和 `(1605, -1456)`。快照是本地测试输入，不提交含整合包数据的 JSON。
- 原版夹具：仓库的 `tests/fixtures/worldgen/overworld.json`，种子 917，区域 `(-49, 33)` 和 `(127, -65)`。
- 每个场景/步长取两个区域各 5×5 个相邻占地，共 50 个请求；步长分别为 1/2/4 方块。各请求的顶面使用完整列生成确定，生成请求的时间不计入测速；底面为海平面下 16 方块。
- 候选复用方法按噪声格持有工作区。该候选只适用于无需完整列顺序的图；完整列/有状态图仍走原路径。逐请求比较每一高度的非空气并集及锚点拒绝结果，交替顺序跑 6 轮，取舍弃首轮后的中位耗时。
- 有计数器的构建统计原生块查询、噪声叶和图求值次数；无计数器的 release 构建给出主耗时。所有统计都是该补采样阶段，不包括地表规则、生物群系、植被、Java/JNI、磁盘、网格或上传。

| 场景 | 步长 | 原路径 → 批量复用（无计数器，50 请求） | 本阶段加速 | 噪声叶求值：原 → 候选（有计数器） | 图求值：原 → 候选 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 玩家山体 | 1 | 7.872 → 2.259 ms | 3.49× | 17,780 → 3,332 | 209,264 → 66,725 |
| 玩家山体 | 2 | 10.691 → 5.059 ms | 2.11× | 24,752 → 7,280 | 331,643 → 151,786 |
| 玩家山体 | 4 | 21.109 → 13.120 ms | 1.61× | 40,516 → 19,236 | 629,065 → 384,226 |
| 原版夹具 | 1 | 8.952 → 2.485 ms | 3.60× | 15,758 → 2,521 | 149,733 → 40,627 |
| 原版夹具 | 2 | 8.323 → 3.625 ms | 2.30× | 15,756 → 5,679 | 151,458 → 67,691 |
| 原版夹具 | 4 | 8.616 → 8.525 ms | 1.01× | 15,574 → 15,574 | 150,508 → 150,508 |

原生块查询次数在每一组内相等；减少的是共享工作区避免的重复密度、噪声初始化与求值。两种输入、三个步长的所有结果在六轮中逐项一致。原版 4 方块样本证明“批量”不是普遍更快，应按同一噪声格的预计复用量决定是否启用。

## 正式有界批次

接缝 BFS 每次最多取 8 个待检查位置。Rust 在调用之前检查密度图是否需要完整列顺序或包含有状态查询，并预检 8 个请求是否有跨请求的水平噪声格重合、整个批次是否只占用至多 8 个格；不满足条件时回到原来的逐请求占地扫描。Java 采样器沿用逐请求算法；较旧的 Rust 原生库不含新 JNI 入口时也回退逐请求。批次的密度工作区和布尔结果都只在本次调用中存活，不写入全局缓存。取消状态在批次前后检查。

这张表与上面的 50 请求无限制候选采用同一份山体快照和相邻坐标，但按生产实现分成最多 8 个请求一批、每批重新检查复用条件。交替顺序执行 6 轮并舍弃首轮取中位数；它只测 **Rust 占地补采样**，还不包含 JNI、Java BFS、网格构建、磁盘或上传，不能推算整个世界加载提速。

| 玩家山体步长 | 批次命中 / 总批次 | 逐个 Rust → 正式批次含回退 | 此阶段加速 |
| ---: | ---: | ---: | ---: |
| 1 | 7 / 7 | 6.486 → 2.960 ms | 2.19× |
| 2 | 7 / 7 | 10.879 → 7.111 ms | 1.53× |
| 4 | 1 / 7 | 24.303 → 24.139 ms | 1.01× |

同一次 66×66 山体网格回放还分别检查了 `(-4588,-1531)` 和 `(1605,-1456)`，步长 1、2、4 的最终占用、高度、标记与旧 Rust/Java 完整列输出一致；网格顶点数也一致。直接 JNI 两请求断言确认这份山体密度图确实进入批量原生入口且结果与逐个 Rust 占地逐高度一致。完整列对照的耗时不能当作“批量优化带来的倍数”，因为其扫描算法本来就不同。

候选在两个相隔较远区域合计 50 个请求结束时，水平格工作区保留的 scratch 容量：实际山体 1/2/4 方块分别为 256,768 / 570,560 / 1,654,016 字节；这是离线测试的临时工作区保留量，不是新增全世界缓存，也没有统计整个模组内存。未来生产实现须限制每批规模和工作区数量，并按世界、结构状态及任务生命周期隔离。

## 区间证明的现有命中

另对同组 50 个坐标单独执行带现有区间证明的地表密度搜索，计数不参与上述耗时对照。真实山体的整个水平格证明有约 89%～91% 被证实非正，其余回到逐列区间；逐列区间中约 43%～47% 为未知。原版夹具整个格有约 96%～97% 被证明非正，逐列区间仍有约 59%～65% 为未知。未知主要出现在不能由当前边界决定符号的区域；它不是错误，也不能直接当作“可省去”的全部计算。由于这些计数对应地表搜索，而表格对照的是洞口占地扫描，不能用两者计算全链路加速百分比。

现有空格证明已覆盖绝大多数完整格。再写通用边界算法的收益尚无数据支持；适合先按节点类型和实际耗时统计未知回退，仅在能够给出严格边界、且材料/含水层/结构语义不变时扩大适用范围。

## 结论与复现

有界的同噪声格批量复用已接入 NeoForge 1.21.1 与 Forge 1.20.1 两套源码和随包的五平台原生库。Rust 常规测试、真实山体 JNI 回放与两套 Gradle 完整构建已通过。带结构影响、有状态图、并发取消和整游戏帧率尚缺现场专项测量；上述阶段倍数不可解释成整世界加载或 FPS 提升。

从原生 crate 目录执行默认夹具：

```powershell
cargo test --release --features profiling --lib exterior_batch_probe::adjacent_footprint_reuse -- --ignored --nocapture
```

指定自己的只读世界生成快照：

```powershell
$env:VSS_SAMPLING_DOCUMENT='C:/path/to/worldgen.json'
$env:VSS_SAMPLING_SEED='5052304137288917019'
cargo test --release --features profiling --lib exterior_batch_probe::adjacent_footprint_reuse -- --ignored --nocapture
```

不带 `--features profiling` 可测不插入原生计数器的 release 耗时。原生 lib 常规测试结果为 33 项通过、4 项条件忽略、0 失败。原始输出保存在工作区被 Git 忽略的 `sampling-*.log` 和 `build/batch-production-bench.log`。
